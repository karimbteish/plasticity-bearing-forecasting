# Data provenance and protocol

## Verified source

The six feature tables used in this project have Git blob SHA-1 values
identical to the files listed by the upstream repository at commit
`f8a40f9ec0b47aac027e69f631c1deb79c7bef66`. Local SHA-256 checksums and upstream paths
are recorded in `provenance.json`. Verification date: 20 October 2026.

Upstream processed data and documentation:
https://github.com/fatemeh-studio/nasa-bearing-anomaly/tree/f8a40f9ec0b47aac027e69f631c1deb79c7bef66

Original dataset: IMS Bearing Data Set, University of Cincinnati's Center for
Intelligent Maintenance Systems, with Rexnord; distributed through NASA Ames PCoE.
Official catalog: https://data.nasa.gov/dataset/ims-bearings
Original citation: J. Lee, H. Qiu, G. Yu, J. Lin, and Rexnord Technical Services
(2007), Bearing Data Set, NASA Ames Prognostics Data Repository.

The NASA catalog says `other-license-specified` and links U.S. government-work
guidance. The upstream repository's MIT license applies to its code; its data
documentation treats data terms separately. Collector and distributor
acknowledgements are retained. This repository provides access code and checksums;
it does not redistribute original waveforms or the processed CSVs.

## Scope of verification

The waveform-to-feature extraction has not been independently rerun. Raw-data
spot-checks in the first project week will examine file counts, acquisition times,
RMS, excess kurtosis and the PSD-band definitions on early/late observations. The
third run's 6,324-row count follows the supplied and upstream tables and requires
checking against the complete nested archive. The current evidence verifies
processed-table provenance; it does not independently validate waveform extraction
or every spectral feature definition.

## Feature dictionary (channel 1 of each bearing)

| Group | Number | Columns | Upstream units |
|---|---:|---|---|
| Amplitude | 3 | rms, std, max | g |
| Shape ratios | 4 | crest_factor, shape_factor, impulse_factor, clearance_factor | dimensionless |
| PSD summary | 2 | psd_mean, psd_std | g²/Hz |
| Defect-band sums | 6 | bpfo_energy, bpfi_energy, bsf_energy and corresponding env_ columns | sums of PSD bins, g²/Hz as documented upstream; not automatically physical energy |
| Distribution shape | 3 | kurt, skew, env_kurtosis | dimensionless; kurtosis is excess kurtosis |
| Spectral ratios | 2 | spectral_entropy, high_freq_ratio | dimensionless |

Each of the 20 features has a six-observation rolling mean after its log/signed-log
transform. Thus there are 40 inputs. This trailing average spans five intervals
(about 50 minutes) across six snapshots; it is not a continuous one-hour waveform
average. The moving-average baseline is the mean of log-RMS, equivalent to the log
of geometric-mean RMS, not the log of arithmetic-mean RMS.

## Static-baseline protocol

1. The raw and spectral tables are joined by unique `file_index`. Alignment,
   timestamp uniqueness and order, and absence of missing entries are checked.
   Only Tests 1 and 2 enter the baseline evaluation.
2. A contiguous trailing shutdown is identified when every bearing's RMS falls
   below 20% of its first-200-observation median. This removes no rows in Test 1
   and two rows in Test 2.
3. A new segment begins whenever the timestamp interval is outside 9–11 minutes.
   Irregular stretches are excluded from forecasting pairs rather than interpolated;
   the data audit reports retention counts.
4. Rolling features use observations within each segment. Each bearing's first
   200 observations calibrate fixed means and standard deviations and are excluded
   from fitting and scoring. They are not assumed to be certified fault-free.
5. Eligible targets occur six rows ahead within the same segment and 60 ± 1 minutes
   later. Inputs require a complete six-observation history and index at least 200.
6. Ridge is fitted on Test 1 and its penalty is selected on Test 2. Training scores
   are in-sample. No Test-3 model predictions are generated by the baseline scripts.
7. Late-life metrics select targets in the final 10% of elapsed live-run time for
   bearings with documented terminal failures. This retrospective analysis subset
   is neither a feature nor an online warning rule.

Prediction records preserve input and target indices and timestamps. In the
planned streaming experiment, an update at time t uses a pair only when
`target_time <= t`; labels are released chronologically.

Test 3 has been inspected descriptively and is therefore called an evaluation run
rather than a pristine blind external test. Its model scores remain outside
hyperparameter selection.
